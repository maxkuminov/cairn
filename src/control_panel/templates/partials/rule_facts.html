{{ m.icon("checkCircle", size=15, stroke=1.9) }} What a rule does
From the next scan, an ordinary change to a matching file is recorded{% if c.ots != "none" %} and re-stamped{% endif %} but not flagged and not alerted on — the way every file behaves in a Working collection, for these files only.
  • Matching files are still watched: compared on every scan, re-read in full by the deep verify, and notarized if the collection is.
  • A rule accepts nothing. Changes already listed for review stay listed until you accept them.
  • Removing a rule changes nothing about files already recorded; later changes to the files it matched follow the collection's policy.
{{ m.icon("alert", size=15, stroke=1.9) }} What a rule never covers
These are flagged for a matching file exactly as for any other:
  • Deletions. There is no rule for a file that disappears.
  • Possible corruption — contents that changed while the size and date did not.
  • A file that comes back different after going missing.
    • {% if mass|default(none) %}
  • An unusually large change in one scan — across the collection, not to one file: when the changes a scan would let pass reach both {{ "{:,}".format(mass.files) }} files and {{ mass.percent }}% of the collection, all of them are flagged instead. It counts one scan's quiet changes together, whichever rule let them pass — a handful of matching files changing never comes near it.
    • {% endif %}
  • A further change to a file whose earlier change you have not accepted yet: it stays listed.
Anything else that happens to a matching file's contents — however large the edit — is not flagged. That is what the rule is for; match only files where that is what you want.
