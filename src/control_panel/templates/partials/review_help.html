{% import "_macros.html" as m %} {# What the accept actions do, and how to get files back instead. Rendered AFTER the list of files on every review surface: an operator arriving from an alert must reach the first file without scrolling past instructions. `root` (optional) names the collection root for the restore steps; `copy_note` (optional) is the truncated-copy-list notice. Two claims are never made here (spec: "Issues are resolved by actions named for their outcome"): that accepting a change can be undone by a rescan, and that accepting a deletion deletes a proof. And one promise is never made: that restoring an EARLIER version of a changed file clears its issue — the scan compares against the newest contents it recorded. #}
{{ m.icon("checkCircle", size=15, stroke=1.9) }} What the actions do
Accept change
This is the file now. Cairn recorded the new contents when it found the change; accepting clears the issue, and this change is not reported again. No earlier version is kept on record to compare against.
Accept deletion
Cairn forgets the file: its record, its first-seen date and the link to its timestamp proof are removed. Nothing on disk is deleted and the proof file stays in the proof store, but the file is no longer listed under Verify.
{{ m.icon("download", size=15, stroke=1.9) }} To get files back instead
Cairn watches your files read-only — it never restores them itself. Copy the affected paths with Copy paths, restore them with your own backup tool (restic, Borg, rsync, Time Machine, a cloud sync…), then run Scan now on the collection.
  • A missing file that comes back is re-read and compared against the fingerprint recorded before it went missing. If it matches, the issue closes by itself. If it does not — the wrong snapshot, a truncated restore — the missing alert is closed and replaced by a new came back different issue for you to check.
  • A changed file is compared against the newest contents Cairn recorded, so putting an earlier version back shows up as one more change, which you then accept.
  • For files you don't want back, use Accept deletion.

How to recover (any backup tool)
  1. Copy the affected paths with the Copy paths button (relative to the collection root) or Copy full paths.
  2. In your backup tool, restore exactly those paths to the collection root {{ root }}.
  3. Run Scan now on the collection page. A missing file that reappeared with the recorded contents returns to healthy; one whose contents differ is flagged came back different — check that one before you trust it.
  4. For anything you don't want back, use Accept deletion — for a folder, or one file at a time from its row.
